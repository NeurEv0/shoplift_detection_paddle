# 容器检测手工标注规范（labelImg / Pascal VOC）

> 第一阶段使用 **labelImg** 手工标注，输出 **Pascal VOC（XML）** 格式，再通过
> `scripts/labelimg_voc_to_coco.py` 转换为 PaddleDetection RT-DETR 训练的 **COCO JSON**。
> 本文档定义：标什么、不标什么、边界情况怎么处理、标注质量如何保证。
>
> 配套文档：标签体系与上报任务适配性分析见 `taxonomy_analysis.md`。
>
> **当前标签体系：9 类**（`trolley` 顾客自带拉车、`cooler_bag` 保温袋为候选类别，调研定稿前**不加入标签、暂不标注**，见 1.3）。

## 1. 标注目标与范围

### 1.1 标注目标（容器）

只标注画面中**可作为藏匿目标或正常购物装载目标**的容器，共 9 类：

| 角色 | 类别 |
|---|---|
| 私有/可疑容器（private） | `bag`、`backpack`、`handbag`、`suitcase` |
| 上下文判定容器 | `plastic_bag`（散称/自带/收银装袋，用途不区分） |
| 正常购物容器（normal） | `basket`、`cart` |
| 特殊容器（special） | `stroller`、`helmet` |

### 1.2 明确不标注的对象

- **商品本身**（货架上的商品、顾客手持的商品）——本阶段不标商品，商品位置由「持商品手部 ROI 代理区域」承担。
- **人、头部、手部、购物车内的商品**——只标容器本身。
- **衣物/口袋/袖口/身体区域**——由姿态关键点+人员框几何派生（`clothing_region`/`pocket_region`），**不属于容器检测模型**，不要画框。
- **货架、收银台、购物篮/车内的商品、标牌、宣传画上的容器图案、影子、玻璃反射**。
- **员工工服口袋/围裙**——不作为容器。
- **收银台待售的新购物袋**（作为商品陈列）——不是正在被使用的容器。
- **完全看不到的容器**（如全部被遮挡、只露出半条背带）。

### 1.3 候选类别（暂不标注，等待调研讨论）

以下对象**当前没有对应标签**，一律**不标注**；遇到时在「争议样本清单」中记录（见 6.1），待类别定稿后统一补标：

- **顾客自带的拉杆购物车/折叠购物车/带轮购物袋**（候选 `trolley`）——不要按 `cart` 标（会引入错误类别语义）。
- **保温袋/冰袋/冷藏袋**（候选 `cooler_bag`）——按 `bag` 标注（软容器，风险角色一致），并在争议清单中记录，待 `cooler_bag` 定稿后回改。

### 1.4 标注者不需要判断的事

- 不需要判断「这个袋子是不是用来偷盗」——风险角色由下游规则层按区域/上下文判定。
- 不需要区分「散称袋 vs 自带塑料袋」——一律标 `plastic_bag`。
- 不需要区分「结账袋 vs 普通袋」——一律标 `bag`。

## 2. 类别定义与标注口径

> 每一类给出「定义 / 标 / 不标 / 边界情形」。判定顺序冲突时见第 4 节。

### 0 `bag` — 通用软包/购物袋（private）

- **定义**：顾客自带的软质容器：购物袋、帆布袋、纸袋、编织袋、托特包、保温袋（候选类别定稿前）、不明软包。
- **标**：顾客手提、肩挎、拎在手上的袋子；放在地上/购物车里的顾客袋子；收银台正在被顾客使用的袋子。
- **不标**：收银台陈列待售的新购物袋；员工围裙口袋。
- **边界**：能明确看出是手提包 → `handbag`；能明确看出是背包 → `backpack`；否则归 `bag`（宁粗勿错）。

### 1 `backpack` — 双肩/单肩背包（private）

- **定义**：背包、双肩包、书包、单肩斜挎书包。
- **标**：背在人身上、拿在手上、放地上的背包都标。
- **不标**：手提包/手抓包（→ `handbag`）；软质斜挎小包（→ `bag` 或 `handbag`）。
- **边界**：背着但被身体遮挡 >50% 的 → 见 3.3 difficult；只露一条背带 → 不标。

### 2 `handbag` — 手提包/钱包（private）

- **定义**：手提包、钱包、手抓包、clutch、小托特包（手提/挽在手臂上）。
- **标**：挽在手臂、提在手上、放在购物车里的手提包。
- **不标**：斜挎软袋（→ `bag`）；背包（→ `backpack`）。

### 3 `suitcase` — 行李箱（private）

- **定义**：行李箱、拉杆箱、旅行箱、带轮拉杆行李。
- **标**：放在地上、推行中、放在购物车旁/上的行李箱。
- **边界**：带拉杆+轮子且是**箱体结构** → `suitcase`；开放式布料车体（顾客自带拉车）→ 候选类别，暂不标注（见 1.3）。

### 4 `basket` — 店用购物篮（normal）

- **定义**：超市提供的购物篮：手提篮、带轮小篮（未大到算购物车）。
- **标**：顾客手提、放地上的店用购物篮。
- **不标**：散称区塑料盒/托盘；顾客自带收纳篮（少见，按 `bag` 或跳过）。
- **边界**：带轮且明显是购物车结构 → `cart`。

### 5 `cart` — 店用购物车（normal）

- **定义**：超市提供的大型购物车/购物推车，含带儿童座椅的购物车。
- **标**：整个可见车体（篮筐+轮子）一个框；儿童座椅购物车也标一个框。
- **不标**：顾客自带的拉杆小车/折叠购物车（候选 `trolley`，暂不标注，见 1.3）；商品本身。
- **边界**：只看到购物车一角（<40% 可见）→ 跳过或 difficult。

### 6 `plastic_bag` — 塑料袋（角色由下游判定）

- **定义**：透明/半透明/不透明塑料袋：散称袋、顾客自带袋、收银装袋。
- **标**：顾客手持、挂在购物车/购物篮上、放地上的塑料袋。
- **不标**：套在垃圾箱上的塑料袋（非购物容器）；完全瘪掉贴在商品上看不清的。
- **边界**：**不区分用途**，是塑料袋就标 `plastic_bag`。与 `bag` 的区别：明显塑料材质且透明/半透明 → `plastic_bag`；不透明软布/纸/编织材质 → `bag`。

### 7 `stroller` — 婴儿车（special）

- **定义**：婴儿车/童车。
- **标**：**载物篮筐/车体**一个框（不要把人一起框进去）；空车也标。
- **不标**：婴儿车里的商品；坐在车里的婴儿。
- **边界**：只露出车轮/扶手 → 跳过；车体+婴儿被遮挡较多 → difficult。

### 8 `helmet` — 头盔（special）

- **定义**：摩托车/自行车/硬壳头盔。
- **标**：头盔**壳体外接框**；戴在头上正常佩戴的也标；拿在手里/放车上的也标。
- **不标**：软帽/棒球帽；头上的头发。
- **边界**：只看到头盔顶部圆弧 → 按头盔标（硬壳特征明显时）。

## 3. 全局标注规则

### 3.1 什么情况必须标

- 容器**完全可见**（类型明确）。
- 容器部分被遮挡，但**可见部分 ≥ 50% 且类型可判断**——按完整外接框标注（可估计被遮挡部分）。
- 容器被顾客拿在手里/背在身上/放在购物车里——只要是「正在被使用/携带」的容器就标。
- 同一画面多个同类容器——**逐个分别标**，不能合并框。
- 一个顾客同时背背包+挎手提包+推购物车——**每个容器各标一个框**。

### 3.2 什么情况不标（直接跳过）

- **高度遮挡**：可见部分 < 40%（如只露半条背带、只露一个轮子），类型不可靠。
- **目标过小**：框短边 < 图像短边 × 2%（1080p 下约 < 22px），检测收益低。
- **严重运动模糊/失焦**，类型无法判断。
- **只出画面边缘**：可见面积 < 20% 且主体在画面外。
- **完全遮挡**（看不见就不存在标注对象）。
- **无法归类**的对象：不标，不设 unknown 类（宁可漏标，不可错标）。
- **候选类别对象**（顾客自带拉车、保温袋）：当前标签体系下没有对应类，**不标注**，记入争议清单（见 1.3）。
- 非实体的容器图案（广告、招牌、镜子/玻璃反射、影子）。
- 员工工作状态中的围裙口袋/工服口袋。

### 3.3 `difficult` 标记（labelImg 勾选 Difficult）

以下情况**要标框，但勾选 Difficult**（转换脚本默认过滤，保证训练集质量；可单独统计）：

- 遮挡 40%~70%，但类型仍可判断。
- 极小目标（短边约为图像短边 2%~4%），但类型可判断。
- 极端角度/模糊/背光，但类型可判断。

> 完全看不清 → 不标；能判断类型但质量差 → 标 + Difficult。

### 3.4 框的绘制规则

- 使用**轴对齐外接框**，紧贴目标边界，包含估计的被遮挡部分。
- 一个目标一个框，不框入无关背景（框入过多无关区域会干扰训练）。
- 对 `stroller`/`helmet` 只框车体/壳体，不框人。
- **斜挎包/背包的背带**：只框包身主体，不把延伸到身体上的背带框进去（会框入大量无关区域）；短提手若完全在包身轮廓内则自然包含，不用刻意剔除。
- 框与框允许轻微重叠（如手袋和背包贴在一起），但不要用一个框包多个目标。
- **同类容器挨在一起**：能看清各自边界（轮廓/提手/颜色可分）→ 各框一个；堆叠挤压、边界不可分的团（如多个塑料袋挤成一团）→ 当一个目标框整团，不要硬切出虚假边界。
- **镜子/玻璃里的反射倒影**：不标。只标真实物体本身；若真实物体不在画面内、只有反射可见，也不标（反射不是独立目标，重复框会干扰下游跟踪与行为判定）。

## 4. 类别优先级判定顺序（解决「好像都能算」）

按以下顺序判定，命中即止：

1. **明显背着/双肩结构** → `backpack`；挽在手臂的小包 → `handbag`；其余软袋 → `bag`。
2. **带拉杆+轮子**：箱体结构 → `suitcase`；开放式布/塑料车体（顾客自带拉车）→ 候选类别，暂不标注。
3. **轮子+推行的车**：店用大金属购物车 → `cart`；个人携带的小型折叠/拉杆车 → 候选类别，暂不标注。
4. **材质特征**：明显保温（厚壁/反光/保温拉链）→ 按 `bag` 标注并记入争议清单（候选 `cooler_bag`）；透明/半透明塑料 → `plastic_bag`；纸/布/编织 → `bag`。
5. **头盔**：硬壳头盔 → `helmet`；软帽不标。
6. **最终兜底**：无法区分 `bag` vs `handbag` vs `backpack` → 选 `bag`（宁粗勿错，角色都是 private）。

## 5. labelImg 操作规范

### 5.1 工具与格式

- 工具：labelImg（https://github.com/HumanSignal/labelImg）。
- 保存格式：**PascalVOC**（默认），输出 XML 到 `Annotations/` 目录，图片放 `JPEGImages/`。
- 类别来源：`datasets/container_det/label_list.txt`（9 类，**顺序即 category id**，转换脚本按此映射）。启动时用启动脚本（见 5.5）或命令行参数把它直接作为类别文件传给 labelImg，**无需单独准备 `classes.txt`**；下拉框与权威标签列表保持同步。

### 5.2 目录结构约定

标注工作区使用本地 `datasets_annotation/`（已 gitignore，原始媒体与标注产物不入库；`datasets/` 为服务器挂载目录，只保留 `label_list.txt` 等配置与最终训练数据）：

```text
datasets_annotation/container_det/
  yulong_store_stride90/              # 一个序列一个目录：{门店}_{摄像头}_{采样间隔}
    images/full/                      # 原始帧（已有，不移动、不修改）
    annotations/                      # ★ labelImg 输出目录：PascalVOC XML（与图片同名）
    coco/                             # （转换后生成）COCO：images/{train,val,test} + annotations/instances_*.json + export_summary.json
  <下一个序列>/...
  merge/                              # （可选）多序列统一训练前的合并暂存：xml/ + jpg/
```

- 一个序列 = 一路摄像头的一段连续时间段；不同门店/摄像头分目录，便于分类统计、抽检与争议追溯。
- `images/full/` 是源图目录，标注过程**不移动、不修改**；转换脚本会把图片复制进 `coco/images/{split}/`。
- labelImg 打开方式：Open Dir 选 `images/full`，Change Save Dir 选 `annotations`（先建好）。
- 多序列统一训练时，可把各序列的 XML 与原图汇总到 `merge/` 后一次性转换（图片名重复时转换脚本会自动加哈希后缀，不会冲突）。

### 5.3 命名规则

- 原图命名：`{store}_{camera}_{timestamp}_{seq}.jpg`（或保持采集系统原名，不做大改）。
- labelImg 自动按图片名生成同名 XML，保持即可。
- 不要重命名已标注图片（XML 内 filename 与文件名绑定）。

### 5.4 操作要点

- 每张图标注前先整体扫一眼，避免漏掉角落的小容器。
- 一个框画完立刻选对类别；同类连续多框时用快捷键（labelImg 支持快捷键 `w` 画框、`d`/`a` 切换图片）。
- 勾选 Difficult 用属性面板的 difficult 复选框。
- 标注完成一张保存一张（`Ctrl+S`），避免丢进度。
- **空图（无容器帧）**：labelImg 只对"改过"的图自动保存，空图必须手动 `Ctrl+S`（会生成无 `<object>` 的空 XML，作为负样本）；大批量可用 `scripts/generate_empty_voc_xmls.py` 扫描兜底生成（先干跑列出、确认无容器后再 `--generate`）。

### 5.5 一键启动（推荐）

用启动脚本 `scripts/launch_labelimg_container_det.ps1` 打开 labelImg，自动配好图片目录 / 类别文件 / 保存目录（首次运行自动创建 `annotations/`）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\launch_labelimg_container_det.ps1
# 标注其他序列（序列目录名 = datasets_annotation\container_det\<名称>）：
powershell -ExecutionPolicy Bypass -File scripts\launch_labelimg_container_det.ps1 -Sequence <序列目录名>
```

- 脚本顶部的 `CondaEnv` / `Workspace` 变量按本机环境修改。
- 前置检查：labelImg 未安装 / 图片目录不存在 / 类别文件不存在时会给出提示并退出，不会误开空窗口（挂载盘临时不可用时同样走友好提示）。

> **PyQt5 兼容说明（Python 3.10 必读）**：PyQt5 ≥ 5.15.5（sip 6）严格要求 `int` 参数，labelImg 的缩放/滚动/画框代码传 `float` 会在启动或标注时崩溃（`TypeError: ... unexpected type 'float'`）。Python 3.10 下所有 pip 版 PyQt5 wheel 均如此，**降级 PyQt5 无效**。本项目采用**源码补丁**修复（已应用）：
>
> - 补丁脚本：`scripts/patch_labelimg_pyqt5.py`，把安装目录里 labelImg 的 8 处 float 调用点包上 `int()`（`setValue` ×4、`drawRect`/`drawLine` ×3、`drawText` ×1），幂等可重复运行。
> - **重装/升级 labelImg 后需重新运行**：`python scripts/patch_labelimg_pyqt5.py`
> - 启动脚本另内置 `QSpinBox/QScrollBar.setValue` 的 `int()` 包装作双保险；源码补丁后直接运行 `labelImg.exe` 亦可。

## 6. 质量控制与数据分布

### 6.1 质量要求

- **类型准确率**：抽查目标 ≥ 95% 类别正确。
- **框紧贴**：抽查目标 ≥ 90% 的框 IoU(标注, 复核) ≥ 0.7。
- **交叉复核**：每批随机抽 10% 由另一人复核，复核差异（漏标/错类/框偏移）记录在案并回改。
- **争议样本清单**：单独维护 `争议样本清单.csv`，记录：图片名、争议点（类别/是否应标/遮挡程度/**候选类别对象**）、最终结论，用于后续规则与规范修订及候选类别调研。

### 6.2 数据分布目标（第一批建议）

| 维度 | 目标 |
|---|---|
| 各类框数 | 每类 ≥ 300 框（低频类如 suitcase/helmet 可 ≥ 100 框） |
| 负样本（无容器帧） | 占总图 10%~20%（训练时 `allow_empty` 已开启，负样本抑制误检） |
| 场景多样性 | ≥ 3 个门店/摄像头角度；白天/夜晚/背光；客流高峰/低谷 |
| 目标尺寸 | 大、中、小目标都要有（小目标 ≥ 10%） |
| 遮挡分布 | 无遮挡/部分遮挡/difficult 都要有（difficult 约 10%~15%） |

### 6.3 候选类别调研配合

- 标注过程中遇到顾客自带拉车、保温袋时**不要标**，但在争议清单中记录**出现频率与图片名**，为 `trolley`/`cooler_bag` 是否新增提供第一手数据。

## 7. 标注 → 训练 → 辅助标注闭环

### 7.1 第一批手工标注（当前阶段）

1. 按 `label_list.txt`（9 类）准备 labelImg 的 `classes.txt`。
2. 组织原图 → 用 labelImg 逐张标注（PascalVOC）。
3. 质检（交叉复核 + 争议清单）。
4. 转换为 COCO：

```powershell
python scripts/labelimg_voc_to_coco.py `
  --xml-dir datasets_annotation/container_det/yulong_store_stride90/annotations `
  --image-dir datasets_annotation/container_det/yulong_store_stride90/images/full `
  --label-list datasets/container_det/label_list.txt `
  --output datasets_annotation/container_det/yulong_store_stride90/coco `
  --val-ratio 0.2 --seed 2026 --include-empty
```

> 每序列转换到自己的 `coco/`；先看 `coco/annotations/export_summary.json` 核对各类框数、difficult 数与负样本数再进入训练。

输出 `annotations/instances_train.json`、`instances_val.json` 与 `images/train|val/`。

### 7.2 训练预训练模型（辅助标注基础）

- 配置：`shoplift/configs/paddledetection/container_det/`，`num_classes` 保持 **9**。
- 训练命令（见 `datasets/container_det/README.md` 基线部分）。
- 导出模型 → 用于后续辅助标注（对未标注帧跑检测，人工只修正）。

### 7.3 模型辅助标注（第二、三阶段）

- 方式一：导出模型对未标注帧推理，输出候选框 → 人工在 labelImg 中**修正而非重画**。
- 方式二：GroundingDINO 预标注（提示词随当前 9 类生成；若后续新增 `trolley`/`cooler_bag` 再增补别名）。
- 每次人工修正后的数据回流训练，迭代提升。
